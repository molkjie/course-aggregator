# ADR-001. Використання шарової архітектури (Layered Architecture)

Статус: прийнято, 2026-11-04

Контекст. Проєкт вимагає високої підтримуваності, ізольованості бізнес-правил та можливості зміни СУБД чи зовнішніх API без переписування основної логіки.

Розглянуті варіанти:
1) Монолітна структура без шарів (все в одному модулі views/models) — простіше для швидкого старту, але призводить до сильної зв'язності коду та ускладнює тестування.
2) Шарова архітектура (Domain -> Services -> Storage/Sources -> API) — чітке розділення обов'язків, інваріанти предметної області ізольовані від зовнішніх бібліотек.

Рішення. Обрано шарову архітектуру з чистим доменним шаром на базі dataclasses.

Наслідки. Потребує написання додаткових DTO/Pydantic схем та адаптерів, проте забезпечує 100% покриття домену швидкими модульними тестами без підключення до БД чи мережі.

Умова перегляду. Перехід на мікросервісну подієво-орієнтовану архітектуру при зростанні навантаження.
